# Group Project: String Compression

## 1. Project Description

For this project, your main task is to investigate the problem of data compression, specifically focusing on lossless compression techniques. While it might seem like a behind-the-scenes utility, data compression is actually a fundamental concept in computer science with massive real-world implications. It allows us to efficiently manage limited storage, transmit data rapidly over networks, and forms the backbone of ubiquitous technologies like ZIP file archivers and PNG image formats.

To get started, you should research and compare the following core algorithms:

- Run-Length Encoding (RLE)
- Huffman Coding
- The Lempel-Ziv-Welch (LZW) algorithm

For a solid theoretical foundation, it's recommended to read **Chapter 16: Greedy Algorithms** (specifically the section on Huffman codes) in *Introduction to Algorithms* (3rd Edition) by Thomas H. Cormen. It covers the mechanism and mathematical justification for building optimal prefix codes in detail.

## 2. Research

### 2.1 Coding

You will develop a command-line utility to read an input text file, compress or decompress it using a specified algorithm, and output the result.

```
Usage: compressor[.exe] -a [algorithm] -m [mode] -i [input_file] -o [output_file]

Options:
  -a [algorithm]   Select algorithm: rle, huff, lzw
  -m [mode]        Select mode: c (compress), d (decompress)
  -i [input_file]  Path to the source file
  -o [output_file] Path to the resulting file
```

> **Important:** Code will be compiled using the GNU g++ compiler with the C++17 standard, using exactly:
> ```
> g++ file1.cpp [..] -o compressor[.exe] -std=c++17
> ```
> Any submission containing non-standard libraries will fail to compile and may receive a grade of **0**.

**Input:**
- Compression Mode (`-m c`): a standard text file containing standard ASCII characters.
- Decompression Mode (`-m d`): a previously compressed file generated by your tool. Depending on the algorithm (Huffman or LZW), this file might contain binary data rather than human-readable text.

**Output:**
- File Output: the tool must generate the resulting compressed or decompressed file and save it to the specified `-o` path.
- Console Output: print the performance summary to standard output, separated by a dashed line.

**Notes on performance metrics** — at the end of every compression execution, output a performance summary containing:

- **Execution Time:** measured in milliseconds (ms) for the core algorithm
- **Compression Ratio:** `Uncompressed Size (bytes) / Compressed Size (bytes)`
- **Space Savings:** `1 − (Compressed Size / Uncompressed Size)`

**Example** — compressing `puzzle.txt` containing `AAAAABBBBBCCCCCDDDDD` with RLE:

```
Compression complete.
--------------------------------
Algorithm: RLE
Execution Time: 0.05 ms
Original Size: 20 bytes
Compressed Size: 8 bytes
Compression Ratio: 2.5
Space Savings: 60.0%
```

*(20-byte input compresses to 8 bytes, e.g. `5A5B5C5D` → 60% space savings.)*

### 2.2 Experiments

Benchmark your algorithms to verify efficiency and scaling, varying input parameters to generate meaningful analytical data:

- **Scenario 1 (Impact of File Size):** fix the data type (standard English text). Run tests with increasing file sizes from small (10 KB) to large (10 MB).
- **Scenario 2 (Impact of Data Entropy):** fix the file size to a medium value (~1 MB). Run tests on different data types: highly repetitive text (e.g. repeating "AAAAABBBBB"), standard English prose, and completely randomized character strings.
